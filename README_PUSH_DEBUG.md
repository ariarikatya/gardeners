# Инструкция по деплою и диагностике Push-уведомлений на iOS (Anemon Agro)

## Инструкция по деплою (Обязательные шаги перед релизом)

1. **Применение схемы БД:**
   Перед деплоем или во время сборки обязательно выполните обновление схемы базы данных, чтобы создалась таблица `ClientPushLog`:
   ```bash
   npx prisma db push --accept-data-loss
   # или при использовании Prisma Migrate:
   npx prisma migrate deploy
   ```
2. **Безопасный деплой и авто-версия:**
   Выполняйте деплой исключительно через безопасный цикл `npm run deploy` (`npm run build && pm2 restart anemon --update-env`). Подробнее см. [DEPLOY.md](./DEPLOY.md).

## Пошаговый чек-лист для проверки и сбора данных с устройства заказчика

### Шаг 1. Открытие приложения и проверка версии
1. Откройте приложение **Anemon Agro** обязательно с **иконки на Домашнем экране** iPhone (PWA/standalone режим).
   - *Важно:* Если на экране устройства несколько иконок Anemon Agro — удалите все старые и оставьте только последнюю созданную иконку.
2. Вверху в кабинете садовника возле кнопки «Уведомления» найдите строку самодиагностики.
3. **Сделайте скриншот** экрана с этой строкой. В ней видны 4 параметра:
   - `v1.0.0-YYYYMMDD-sha` (версия клиенского бандела и кэша);
   - `mode` (`standalone` — приложение запущено с иконки, `browser` — вкладка Safari);
   - `perm` (`granted`, `denied`, `default`);
   - `sub` (`yes` — активна, `no` — отключена, `lost` — подписка на устройстве потеряна).

### Шаг 2. Настройка push-уведомлений и тест доставки
1. Нажмите кнопку **«Включить уведомления»** (или **«Восстановить подписку»**).
2. В системном всплывающем окне iOS выберите **«Разрешить»**.
3. Нажмите появившуюся кнопку **«🧪 Отправить тест»**. Сообщите разработчику, пришло ли всплывающее push-уведомление.
4. При наличии флага `staleClientDetected=true` — полностью закройте все вкладки WebApp (смахиванием вверх из меню приложений iOS) и переоткройте с иконки.

## Белый экран у пользователя (Диагностика сервером)

Если пользователь сообщат о белом экране на смартфоне:
1. **Сначала откройте pm2 logs на сервере VPS:**
   ```bash
   pm2 logs anemon --lines 50
   ```
2. **Характерные ошибки в логах:**
   - `Could not find a production build in the '.next' directory` (pm2 перезапущен без окончания сборки);
   - `Failed to find Server Action "x"` (несоответствие версий клиента и сервера / version skew);
   - `TypeError: Cannot read properties of null (reading 'digest')`.
3. **Решение:**
   Причиной является полуснесённый или протухший билд на сервере. Проблема лечится **полным пересозданием билда и перезапуском pm2 на сервере по инструкции `DEPLOY.md`**, а НЕ повторной чисткой кэша на телефоне пользователя!

## Бесшовные обновления PWA (Переустановка PWA НЕ требуется)

Переустановка приложения и удаление иконки с экрана iPhone после деплоев больше НЕ требуется. Приложение обновляется бесшовно при открытии:
- Заголовки `/sw.js` и `/manifest.json` отдаются с `Cache-Control: no-cache, no-store, must-revalidate`.
- Если у пользователя открыта старая вкладка, компонент `BuildVersionWatcher` покажет баннер обновления.
- При следующем возврате на вкладку приложение выполнит мягкое авто-обновление.
- Состояние push-подписки и разрешения iOS сохраняются при обновлениях (код обновления никогда не вызывает `unsubscribe()`).

Для проверки параметров сборки соберите JSON из `/api/push/diagnose`:
- `swCacheName`: имя кэша сервис-воркера;
- `latestServerBuildVersion`: актуальная версия сервера;
- `expectedClientMismatch`: совпадение версий;
- `swFetchHeaders`: заголовки ответа `/sw.js`;
- `lastDeliveryAttempt`: статус последней отправки push-уведомления (`{ ts, statusCode, expired }`).
