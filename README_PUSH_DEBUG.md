# Руководство по диагностике и отладке Web Push подписок

## Отслеживание анонимных подписок (userId = null)

В проекте подписки Web Push сохраняются в таблице `PushSubscription`.
Если браузер регистрирует подписку до завершения авторизации пользователя, запись создаётся с `userId = null`.

### Диагностика через API

Эндпоинт `GET /api/push/diagnose` предоставляет полные метаданные по подпискам:

- `unlinkedSubscriptionsCount` — количество подписок с `userId = null` («НЕ ПРИВЯЗАНА»).
- `totalSubscriptionsCount` — общее количество зарегистрированных push-подписок.
- `subscriptions` — подробный список подписок с флагом владельца, типом браузера/провайдера (`apple`, `fcm`, `mozilla`) и ID.

### Автоматическая привязка (Backfill)

При первом же авторизованном запросе к `POST /api/push/subscribe` (например, при авто-входе или нажатии кнопки «Включить уведомления»):
1. Сервер выполняет автоматическую привязку (`updateMany({ where: { endpoint, userId: null }, data: { userId } })`), заменяя `userId = null` на реальный `userId` текущего пользователя.
2. В рассылке `sendToRoles(['GARDENER'], ...)` подписки с `userId = null` также автоматически подтягиваются для роли `GARDENER`.

### Как переподписать устройство вручную

1. Откройте приложение под нужной учётной записью садовника.
2. Нажмите кнопку «🔔 Отключить уведомления», затем «🔔 Включить уведомления».
3. Выполните проверку через `/api/push/diagnose`: подписка свяжется с текущим `userId`.
